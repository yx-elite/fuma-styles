DNS, the Domain Name System, turns names people can remember into the addresses computers use. It is a large, shared lookup system spread over many servers, and almost every connection on the internet starts with it.

## Key ideas

How a lookup travels, what records hold, and why changes take time to appear.

### How a lookup works

A lookup walks down from the top of the name system until it finds a server that knows the answer.

1. The browser asks the operating system, which asks a **resolver**, usually run by the internet provider.
2. The resolver asks a **root server** where to find `.com`.
3. It asks the **`.com` servers** where to find `example.com`.
4. It asks the **authoritative server** for `example.com`, which holds the real answer.
5. The answer travels back, and every step keeps a copy for its TTL.

Most lookups never get past step 1 or 2, because an answer is already cached somewhere.

### Record types

The records an exam is most likely to ask about.

- `A`: a name to an IPv4 address, such as `93.184.215.14`.
- `AAAA`: a name to an IPv6 address.
- `CNAME`: a name to another name. Cannot be used at the top of a domain.
- `MX`: where email for the domain goes.
- `TXT`: free text, often used to prove domain ownership.
- `NS`: which servers are authoritative for the domain.

<Callout type="idea" title="Alias records">
  Some DNS providers offer an alias record that works like a `CNAME` but is allowed at the top of a domain. Use it to point `example.com` itself at a load balancer or CDN.
</Callout>

### TTL and propagation

Each record has a TTL that tells resolvers how long to keep it.

- **Short TTL** (60 seconds): changes show up quickly, but resolvers ask more often.
- **Long TTL** (a day): fewer lookups, but a change can take a day to reach everyone.

Before a planned change, lower the TTL a day in advance. After the change has settled, raise it again.

```bash
# Show the answer and its remaining TTL
dig example.com A +noall +answer
```

### Routing with DNS

DNS can do more than return one fixed answer.

| Routing | Answers with | Used for |
| --- | --- | --- |
| Simple | One fixed set of addresses | A single server |
| Weighted | Addresses split by percentage | Gradual rollouts |
| Latency-based | The closest Region | Faster responses worldwide |
| Failover | A backup when health checks fail | Disaster recovery |
| Geolocation | An answer per country | Local content or legal rules |

### Exam scenarios

- **Point the bare domain at a load balancer** → use an alias record, because a `CNAME` is not allowed at the top of a domain.
- **Move traffic to a new server slowly** → weighted routing, because it splits traffic by percentage.
- **Users far away get slow responses** → latency-based routing, because it picks the closest Region.
- **A change is not showing up for some users** → wait for the old TTL to run out, because resolvers still hold the old answer.
