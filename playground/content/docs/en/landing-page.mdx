The landing page is built from your notes and `site.config.ts`, so a new site has a complete one with nothing to write. As notes are added, it updates itself.

## What it shows

| Part | Comes from |
| --- | --- |
| Badge, title and description | `tag`, `name` and `description` in the config |
| Page count, section count, last update | Your notes, and their latest git commit |
| Docs preview | A live miniature of the docs, drawn from the sidebar, in the current theme and accent |
| Built with | Notestack, then the libraries every site runs on |
| What's inside | A mosaic with one card for each sidebar section (up to six), each showing the section a different way |
| Get started | `start` in the config |
| Search | Opens the site search |
| Footer | `name`, `description`, `repo` and `author`. Also the sections again, your `links`, and a *Built with Notestack* link |

Moving from the landing page into the docs, and back, is animated. See [Page transitions](/docs/features#page-transitions).

## Get started

By default, the "Get started" section shows how to run the notes on your own machine: clone the repository, install, and run. Set `start` to show your own steps, or `false` to hide it:

```ts title="site.config.ts"
start: {
  title: 'Run the notes on your machine',
  text: 'Three commands, and you can read the notes offline.',
  steps: [
    { title: 'Clone', text: 'Get a copy from GitHub.', command: 'git clone https://github.com/you/notes.git' },
    { title: 'Install', text: 'Install the packages.', command: 'cd notes && npm install' },
    { title: 'Run', text: 'Open localhost:3000.', command: 'npm run dev' },
  ],
},
```

Each step is shown in the list, and its command is typed into the terminal beside it. After the last command, the terminal shows *Ready on http://localhost:3000*. Set `done` in `start` to change that line.

### With an AI agent

Add `agent` to `start` for a second tab, *With your agent*. A switch in the terminal's title bar moves between the two. The agent tab shows three steps (copy, paste, check) beside a chat window: your instructions type in as the reader's message, then each of the agent's steps ticks off. A *Copy instructions* button copies `prompt`, and a *Works with* row links to the coding agents that can follow it, such as Claude Code, Codex and Cursor.

```ts title="site.config.ts"
start: {
  // …title, text and steps as above
  agent: {
    prompt: 'Clone https://github.com/you/notes, run npm install, read node_modules/@yx-elite/notestack/WRITING.md, then add a note on subnets and run npm run build until it passes.',
    steps: ['git clone …/notes', 'npm install', 'Read WRITING.md', 'Wrote subnets.mdx', 'npm run build'],
    done: 'Done. Run npm run dev and open localhost:3000.',
  },
},
```

| Field | What it does |
| --- | --- |
| `prompt` | The instructions the button copies, and the chat's first message |
| `steps` | The agent's work, one short line each, shown ticking off in turn |
| `done` | The last line. Default: *Done. Your site is ready.* |

Point the prompt at `WRITING.md`, the writing guide that ships with the theme, so the agent uses its components and style. Ask for `npm run build` rather than `npm run dev`: the build finishes and fails on a broken page, while the dev server never ends. On a site with `languages`, set `agent` in each language's `start` in `translations`.

## Line breaks and highlights

On the landing page, the title (`name`) and the line under it (`description`) take two marks:

| Mark | Does | Example |
| --- | --- | --- |
| `\n` | Starts a new line | `name: 'AWS SAA-C03\nHandbook'` |
| `*text*` | Puts the words in the accent colour; in the description, over a soft marker stroke | `description: 'Notes that read *beautifully*.'` |

```ts title="site.config.ts"
name: 'AWS SAA-C03\nHandbook',
description: 'Study notes for the Solutions Architect – Associate *(SAA-C03)* exam, topic by topic.',
```

Everywhere else (the header, the sidebar banner, the footer, the browser tab, share images and what search engines show) the marks are left out: "AWS SAA-C03 Handbook". Write `\n` with a backslash; `/n` is just text. In `translations`, mark the words you want in each language, for example `'…发布一个*读起来舒服*的网站。'`.

## Sections

The "What's inside" cards, and the *Notes* column of the footer, follow your [sidebar](/docs/pages#the-sidebar) (`content/docs/meta.json`). Rename or reorder it there and the landing page follows:

- Each section heading (`---Title---`) starts a card, with the pages under it.
- A heading with only one folder under it, right after the heading, keeps that folder's pages on its own card.
- Every other folder gets a card of its own, named after the folder. So a heading over several folders (`---Notes---`, then one folder per topic) is only a heading in the sidebar, and each topic gets its own card.
- Pages before the first heading go on a card called *Start here*.
- *Start reading* opens `/docs`, which is `content/docs/index.mdx`. The docs preview opens the first page of the first card.

The cards form a mosaic of different sizes. Each shows its section a different way, using only what every section has: its name, its page count, its page titles and the pages' `icon:` frontmatter.

| Card | Where | What it shows |
| --- | --- | --- |
| Feature | The first section, tall on the left | The name in large type, the first page's description, every page as a chip, and a link to the first page |
| Cluster | Top right | The pages' icons, overlapping |
| Stack | Below it | The first four pages, one under another |
| Count | Beside the stack | The page count, in large type |
| Strip | The fifth and sixth sections, side by side | The name and the pages as chips, on one line |

A page without an `icon:` shows its number in place of an icon. With fewer than four sections, the mosaic uses fewer, larger cards. On a phone, the cards stack in sidebar order. Every card links to its section's first page.

Up to six sections, every section gets a card. With seven or more, the first four get a card and one row under them takes the rest: it says how many are left ("16 more sections"), links the next four by name, and ends with *See all in the docs*, which opens the first page. The sidebar there lists every section.

## Your own landing page

To change only the wording, such as *Start reading* or *What's inside*, set `text` in `site.config.ts`. [Languages](/docs/languages#built-in-text) explains how.

To change more, write the page yourself. Two files make the landing page:

| File | What it holds | What to do |
| --- | --- | --- |
| `app/(home)/layout.tsx` | `NotesHomeLayout`: the header with search, the theme switch, the language switch and GitHub | Keep it |
| `app/(home)/page.tsx` | `NotesHome`: everything below the header | Replace it |

Keeping the layout keeps the header, search and the animation into the docs working. Everything `NotesHome` draws goes with it: the hero, the docs preview, *Built with*, *What's inside*, *Get started*, the search section and the footer. The footer's *Built with Notestack* link goes too; a link back on your own page is welcome but not required.

### One language

Write the page as a normal React component. It can read `site.config.ts` and your notes through `source`:

```tsx title="app/(home)/page.tsx"
import Link from 'next/link';
import { source } from '@/lib/source';
import site from '@/site.config';

export default function HomePage() {
  return (
    <main className="mx-auto w-full max-w-3xl px-4 py-16">
      <h1 className="text-4xl font-semibold">{site.name}</h1>
      <p className="mt-4 text-fd-muted-foreground">{site.description}</p>
      <p className="mt-2">{source.getPages().length} pages of notes</p>
      <Link href="/docs" className="mt-6 inline-block font-medium text-fd-primary">
        Read the notes
      </Link>
    </main>
  );
}
```

### Several languages

On a site with `languages`, the page is `app/[lang]/(home)/page.tsx` and gets the reader's language from the URL. Three things change:

1. **Read the language.** Next.js passes it as `lang`: `'en'`, `'zh-CN'`…
2. **Keep the page's own words in one object**, with an entry per language. A language without an entry falls back to the default.
3. **Start links with the language**: `/zh-CN/docs`, not `/docs`. Links in the header and in your notes get it added for you; links you write in your own page don't.

`siteFor(site, lang)` gives the config in that language, so `name` and `description` come from `translations`:

```tsx title="app/[lang]/(home)/page.tsx"
import Link from 'next/link';
import { siteFor } from '@yx-elite/notestack';
import { source } from '@/lib/source';
import site from '@/site.config';

// The page's own words, one entry per language in site.config.ts
const words = {
  en: { read: 'Read the notes', pages: 'pages of notes' },
  'zh-CN': { read: '阅读笔记', pages: '页笔记' },
};

export default async function HomePage({ params }: PageProps<'/[lang]'>) {
  const { lang } = await params;
  const local = siteFor(site, lang);
  const t = words[lang as keyof typeof words] ?? words.en;

  return (
    <main className="mx-auto w-full max-w-3xl px-4 py-16">
      <h1 className="text-4xl font-semibold">{local.name}</h1>
      <p className="mt-4 text-fd-muted-foreground">{local.description}</p>
      <p className="mt-2">
        {source.getPages(lang).length} {t.pages}
      </p>
      <Link href={`/${lang}/docs`} className="mt-6 inline-block font-medium text-fd-primary">
        {t.read}
      </Link>
    </main>
  );
}
```

To add a language later, add it to `languages` in `site.config.ts` and an entry to `words`.

### Colours and styles

Tailwind works in your page as it does anywhere in the app. For colours, use Fumadocs' colour classes: they follow the theme and switch with light and dark mode by themselves.

| Class | Colour |
| --- | --- |
| `text-fd-foreground` | Main text |
| `text-fd-muted-foreground` | Quieter text |
| `text-fd-primary`, `bg-fd-primary` | The site's accent |
| `bg-fd-card`, `border-fd-border` | Cards and their edges |

For your own CSS, add it to `app/global.css`, after the two imports. The accent is `var(--ns-accent)`, and the serif used for titles is `var(--ns-font-display)`:

```css title="app/global.css"
@import 'tailwindcss';
@import '@yx-elite/notestack/theme.css';

.my-hero-title {
  font-family: var(--ns-font-display);
  color: var(--ns-accent);
}
```

Name your classes with your own prefix, not `ns-`: the theme's classes can change between versions. Check the page in light and dark mode.

### Going back

Put the theme's page back to get the default landing page again:

```tsx title="app/(home)/page.tsx"
import { NotesHome } from '@yx-elite/notestack';
import { source } from '@/lib/source';
import site from '@/site.config';

export default function HomePage() {
  return <NotesHome site={site} source={source} />;
}
```

On a site with `languages`, pass `siteFor(site, lang)` as `site`, as in [Languages](/docs/languages#update-the-layouts).
