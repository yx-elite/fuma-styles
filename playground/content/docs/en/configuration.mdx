Everything that differs between notes sites lives in `site.config.ts` at the root of your app. The theme reads it for the header, sidebar, landing page and accent colour.

```ts title="site.config.ts"
import { defineSiteConfig } from '@yx-elite/notestack';

export default defineSiteConfig({
  name: 'AWS SAA-C03 Notes',
  author: 'your-name',
  tag: 'SAA-C03',
  description: 'Study notes for the AWS Solutions Architect Associate exam.',
  repo: 'your-name/aws-saa-notes',
  url: 'https://saa.example.com',
  accent: { light: '#d97706', dark: '#fcd34d' },
  links: [
    { text: 'Home', url: '/docs', icon: 'House' },
    { text: 'Glossary', url: '/docs/glossary', icon: 'BookA' },
  ],
});
```

## Accent colours

Pick a deeper shade for light mode and a lighter one for dark mode, so text in the accent colour stays readable on both backgrounds. The theme makes a second tone from it for gradients. Try colours live with the palette button in the corner of this site, then copy the pair you like. More in [Theme and accent](/docs/theme).

## Language

Set `language` to the language your notes are written in. The page's `lang`, dates and every piece of text the theme shows follow it, including Fumadocs' search box, *On this page* and page buttons.

```ts title="site.config.ts"
export default defineSiteConfig({
  // …
  language: 'zh-CN',
});
```

The theme's own text ships in English and Simplified Chinese. For any other language, or to change a single phrase, fill in `text`: [Languages](/docs/languages#built-in-text) lists what's built in and how `text` works.

## Several languages

To publish the same notes in more than one language, list them in `languages` (the first is the default) and put each language's text in `translations`. URLs then start with the language (`/en/docs/…`), notes live in one folder per language, and a language switch appears in the header. It needs a few more files in `app/`: the [Languages](/docs/languages) guide walks through it.

## Site address

Set `url` once the site has an address. A link to one of your notes, pasted into a chat app or a social post, then shows a preview with the note's title. Without it, everything else works the same.

## Quick links

Quick links stay fixed under the sidebar banner while the page list scrolls. Use them for the two or three pages readers open most, such as a glossary or an exam overview. Icons come from [Lucide](https://lucide.dev/icons).

## Sidebar order and titles

The order of pages and the section titles in the sidebar come from `meta.json` files next to your notes, and each page's title, description and icon from its frontmatter. See [Writing notes](/docs/writing-notes#the-sidebar).

## Logo and favicon

The logo in the header and the footer is the Notestack mark, drawn in your accent colour. It can't be swapped for an image yet.

The browser-tab icon is `app/icon.svg`. To use your own, replace that file with another SVG, or delete it and add `app/icon.png` (a square PNG, at least 64 by 64 pixels) or `app/favicon.ico`. Next.js picks up whichever is there.

## Options in the app files

A few options live in the files in `app/` rather than in `site.config.ts`, because they need code.

### Your own components

To use a component of your own in notes, write it in your site, then pass it to `createNotesPage` in `app/docs/[[...slug]]/page.tsx`:

```tsx title="components/exam-tip.tsx"
export function ExamTip({ children }: { children: React.ReactNode }) {
  return <p className="rounded-lg border p-4">💡 {children}</p>;
}
```

```tsx title="app/docs/[[...slug]]/page.tsx"
import { createNotesPage } from '@yx-elite/notestack/routes';
import { source } from '@/lib/source';
import site from '@/site.config';
import { ExamTip } from '@/components/exam-tip';

const docs = createNotesPage({ source, site, components: { ExamTip } });

export default docs.Page;
export const generateStaticParams = docs.generateStaticParams;
export const generateMetadata = docs.generateMetadata;
```

Notes can then use `<ExamTip>…</ExamTip>` without importing it. A component with the same name as one of the theme's replaces it.

### A site inside a bigger repository

If the site isn't at the root of its repository, for example in a `site/` folder, *Open in GitHub* links need the folder. Pass it as `repoDir`:

```tsx title="app/docs/[[...slug]]/page.tsx"
const docs = createNotesPage({ source, site, repoDir: 'site' });
```

### Next.js options

`withNotestack()` in `next.config.mjs` sets what a static site needs. Pass any other Next.js option to it:

```js title="next.config.mjs"
export default withMDX(
  withNotestack({
    env: { NEXT_PUBLIC_EXAM_DATE: '2027-03-01' },
  }),
);
```

It always keeps `output: 'export'`, `trailingSlash: true` and unoptimised images, which the hosting depends on. Don't set `basePath`: the site must be served from the root of a domain, or search stops working.
