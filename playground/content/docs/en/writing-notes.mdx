The theme styles whatever Fumadocs renders, so you write notes the normal Fumadocs way.

## MDX pages

Put `.mdx` (or `.md`) files in `content/docs/`. MDX is Markdown that can also use components, such as tabs, steps and cards.

<Files>
  <Folder name="content/docs" defaultOpen>
    <File name="index.mdx" />
    <File name="meta.json" />
    <Folder name="networking" defaultOpen>
      <File name="vpc.mdx" />
      <File name="route-53.mdx" />
    </Folder>
  </Folder>
</Files>

Each page starts with frontmatter:

```md title="content/docs/networking/vpc.mdx"
---
title: VPC
description: Private networks in AWS, subnets and routing.
icon: Network
---

Your note starts here.
```

To learn the syntax, see the Fumadocs guide to [writing pages](https://fumadocs.dev/docs/next/markdown). Everything it shows is styled by the theme: see the [Showcase](/docs/showcase/markdown#typography).

<Callout type="info" title="Keep your notes in git">
Commit and push to publish. Every change is kept in the history, any computer gets the notes with `git pull`, and the *Last updated* date of each page comes from its latest commit.
</Callout>

## Glossary

The glossary page reads a list of terms from `content/glossary.json`:

```json title="content/glossary.json"
[
  {
    "term": "Subnet",
    "definition": "A range of addresses inside a VPC.",
    "href": "/docs/networking/vpc#subnets",
    "label": "VPC"
  }
]
```

`href` and `label` are optional: they add a link to the note that explains the term. See it on the [Glossary](/docs/glossary) page.
