A notes site is in English unless you say otherwise. There are two levels:

| You want | Set | URLs | Extra files |
| --- | --- | --- | --- |
| The whole site in one language, such as Chinese | `language: 'zh-CN'` | `/docs/…` | None |
| The same notes in several languages, with a switch | `languages: ['en', 'zh-CN']` | `/en/docs/…`, `/zh-CN/docs/…` | Yes, see below |

## One language

Set `language` to the language your notes are written in, as a [language tag](https://www.w3.org/International/articles/language-tags/) such as `zh-CN`, `ja` or `fr`:

```ts title="site.config.ts"
export default defineSiteConfig({
  // …
  language: 'zh-CN',
});
```

The page language, date formats and all the text the theme shows follow it: the landing page, the glossary, *Last updated*, and Fumadocs' own search box, *On this page* and page buttons.

### Built-in text

| Language | Theme's text | Fumadocs' text |
| --- | --- | --- |
| English (`en`) | Yes | Yes |
| Simplified Chinese (`zh-CN`) | Yes | Yes |
| Traditional Chinese (`zh-TW`) | English, unless you fill in `text` | Yes |
| Japanese (`ja`) | English, unless you fill in `text` | Yes |
| Any other | English, unless you fill in `text` | English |

To translate the theme's text into another language, or to change one phrase, fill in `text`. Anything you leave out stays in English:

```ts title="site.config.ts"
export default defineSiteConfig({
  // …
  language: 'fr',
  text: {
    startReading: 'Commencer la lecture',
    pageCount: { one: '{n} page', other: '{n} pages' },
    lastUpdated: 'Mis à jour le {date}',
  },
});
```

Words in braces, such as `{n}` and `{date}`, are filled in by the theme. A text that depends on a number takes one form per plural category of the language: English and French use `one` and `other`, Chinese only `other`. The full list of keys is the `NotesText` type in the package ([source](https://github.com/yx-elite/notestack/blob/main/packages/notestack/src/i18n/text.ts)).

## Several languages

With `languages`, each page exists once per language, and readers switch between them in the header. This site is set up this way: try the language button at the top.

What changes for you:

- **Translate one page at a time.** A page missing in a language shows the default language's page.
- **URLs start with the language**, because a static site can't hide it. Opening `/` sends readers to the language they read last, else the one their browser prefers, else the default.
- **Links stay the same.** Keep writing `/docs/…` in notes, cards, quick links and the glossary: the theme adds the page's language.
- **Search** keeps one index per language and searches the page's language. See [Search](/docs/features#search).

<Callout type="warn" title="Decide early">
Turning `languages` on moves every page to a new URL. Links people saved to `/docs/…` stop working. If you might translate later, it's easiest to set it up before you share the site.
</Callout>

## Set up several languages

These steps turn a site made with `npm create notestack` into a site with English and Simplified Chinese. Swap in your own languages.

<Steps>
<Step>

### List the languages

The first one is the default. Put the site's own text for the other languages in `translations`. Anything you leave out uses the default language's value.

```ts title="site.config.ts"
export default defineSiteConfig({
  name: 'Networking Notes',
  description: 'Study notes for an introductory networking course.',
  repo: 'your-name/networking-notes',
  links: [{ text: 'Glossary', url: '/docs/glossary', icon: 'BookA' }],
  languages: ['en', 'zh-CN'],
  translations: {
    'zh-CN': {
      name: '网络笔记',
      description: '网络入门课程的学习笔记。',
      links: [{ text: '术语表', url: '/docs/glossary', icon: 'BookA' }],
    },
  },
});
```

`translations` can hold `name`, `author`, `tag`, `description`, `links`, `bannerLink`, `start` and `text`.

`text` is the one exception to "anything you leave out uses the default language's value". `text` at the top of the config changes the default language only, so a Chinese page never shows an English phrase you renamed. To change the same phrase in another language, set `text` in that language's `translations`:

```ts title="site.config.ts"
export default defineSiteConfig({
  // …
  languages: ['en', 'zh-CN'],
  text: { startReading: 'Open the notes' }, // English pages
  translations: {
    'zh-CN': { text: { startReading: '打开笔记' } }, // Chinese pages; leave it out to keep 开始阅读
  },
});
```

</Step>
<Step>

### Move the notes into language folders

Move everything in `content/docs/` into `content/docs/en/`. Then create `content/docs/zh-CN/` and add translated pages with the **same file names**:

<Files>
  <Folder name="content/docs" defaultOpen>
    <Folder name="en" defaultOpen>
      <File name="meta.json" />
      <File name="index.mdx" />
      <File name="subnets.mdx" />
    </Folder>
    <Folder name="zh-CN" defaultOpen>
      <File name="meta.json" />
      <File name="index.mdx" />
    </Folder>
  </Folder>
</Files>

Here `subnets.mdx` isn't translated yet, so Chinese readers see the English page. Each folder's `meta.json` sets that language's sidebar order and section names.

</Step>
<Step>

### Move the pages into app/[lang]/

Next.js needs the language as the first part of every page's URL, so the pages move into a folder named `[lang]` (with the square brackets). The search and llms routes and the icon stay where they are:

<Files>
  <Folder name="app" defaultOpen>
    <Folder name="(root)" defaultOpen>
      <File name="layout.tsx" />
      <File name="page.tsx" />
    </Folder>
    <Folder name="[lang]" defaultOpen>
      <File name="layout.tsx" />
      <Folder name="(home)" />
      <Folder name="docs" />
      <Folder name="og" />
    </Folder>
    <Folder name="api" />
    <Folder name="llms.txt, llms-full.txt, llms.mdx" />
    <File name="global.css" />
    <File name="icon.svg" />
  </Folder>
</Files>

1. Move `app/(home)/`, `app/docs/` and `app/og/` into `app/[lang]/`.
2. Move `app/layout.tsx` to `app/[lang]/layout.tsx`, and change it as shown in the next step.
3. Create `app/(root)/` with the two files below.

</Step>

### Update the layouts

The layouts read the language from the URL. Copy these over the moved files:

<Accordions>
<Accordion title="app/[lang]/layout.tsx">

```tsx title="app/[lang]/layout.tsx"
import { Geist, JetBrains_Mono } from 'next/font/google';
import { NotesRoot, notesMetadata } from 'notestack';
import site from '@/site.config';
import '../global.css';

const sans = Geist({ subsets: ['latin'], variable: '--font-sans' });
const mono = JetBrains_Mono({ subsets: ['latin'], variable: '--font-mono' });

// One copy of the site per language in site.config.ts
export const dynamicParams = false;
export function generateStaticParams() {
  return (site.languages ?? []).map((lang) => ({ lang }));
}

export async function generateMetadata({ params }: LayoutProps<'/[lang]'>) {
  const { lang } = await params;
  return notesMetadata(site, lang);
}

export default async function Layout({ params, children }: LayoutProps<'/[lang]'>) {
  const { lang } = await params;
  return (
    <NotesRoot site={site} language={lang} className={`${sans.variable} ${mono.variable}`}>
      {children}
    </NotesRoot>
  );
}
```

</Accordion>

<Accordion title="app/(root)/layout.tsx and page.tsx">

The page at `/`, which sends readers on to their language:

```tsx title="app/(root)/layout.tsx"
import type { ReactNode } from 'react';
import { defaultLanguageOf } from 'notestack';
import site from '@/site.config';
import '../global.css';

export default function Layout({ children }: { children: ReactNode }) {
  return (
    <html lang={defaultLanguageOf(site)}>
      <body>{children}</body>
    </html>
  );
}
```

```tsx title="app/(root)/page.tsx"
import { LanguageRedirect } from 'notestack';
import site from '@/site.config';

export default function Page() {
  return <LanguageRedirect site={site} />;
}
```

### If you've read Fumadocs' guide

Fumadocs has its own [internationalization guide](https://fumadocs.dev/docs/next/internationalization). Notestack sets most of it up for you, and differs in a few places because a notes site has no server. Skip these parts of the Fumadocs guide:

| Fumadocs' guide says | In Notestack |
| --- | --- |
| Create `lib/i18n.ts` with `defineI18n()` | List `languages` in `site.config.ts` |
| Add `proxy.ts` (middleware) to send `/` to a language | Don't: a static site can't run it, and the build fails. `LanguageRedirect` in `app/(root)/page.tsx` does it in the browser |
| Hide the default language from URLs (`hideLocale`) | Not possible without a server. Every URL starts with its language |
| Name translations `page.zh.mdx`, next to the original | One folder per language: `content/docs/zh-CN/page.mdx`. The folder name must match the language in `languages` exactly |
| Pass `i18n` and translations to `RootProvider` | `NotesRoot language={lang}` does it, with the theme's text and Fumadocs' text for that language |

### A glossary per language

The glossary page is a note like any other, so each language has its own. Keep the terms in one file per language and import the right one:

```mdx title="content/docs/zh-CN/glossary.mdx"
---
title: 术语表
---

import terms from '@/content/glossary.zh-CN.json';

<Glossary terms={terms} />
```

Links in the terms (`href`) stay `/docs/…`, and the theme adds the language. How to fill in the terms is on [Glossary](/docs/glossary).

### Add a language later

Add it to `languages` and its text to `translations`, then create its folder, such as `content/docs/ja/`, with a `meta.json`. Pages you haven't translated show the default language's page until you do.

### Known limit

`llms.txt` and `llms-full.txt` list the pages of every language together. See [Copies for AI assistants](/docs/features#copies-for-ai-assistants).
