## Requirements

- [Node.js](https://nodejs.org) 22 or later. Check with `node --version`.
- npm, which comes with Node.js.
- [Git](https://git-scm.com), for *Last updated* dates and to publish your notes.
- A code editor, such as [VS Code](https://code.visualstudio.com).

Notestack builds its own site with Next.js and Fumadocs MDX, as a static export. It doesn't plug into a Fumadocs app set up another way, such as one with a server, another framework or another content source.

## Create a site

<Steps>
<Step>

### Create the site

```bash
npm create notestack@latest my-notes
```

This makes a new folder, `my-notes`, with a notes site already set up to use the theme, and installs everything it needs. Use any folder name you like.

</Step>
<Step>

### Start it

```bash
cd my-notes
npm run dev
```

Open [localhost:3000](http://localhost:3000). The site updates as you save files. Stop it with <kbd>Ctrl</kbd> + <kbd>C</kbd>.

</Step>
<Step>

### Make it yours

Open `site.config.ts` and set your site's `name`, `description` and `repo`. Every option is on the [Configuration](/docs/configuration) page.

The site comes with a short sample that shows each feature once: a welcome page, an `example` folder and a glossary. When you're ready to write your own notes, remove it:

1. Delete `content/docs/example/`, then remove `"...example"` from `content/docs/meta.json`.
2. Replace the text of `content/docs/index.mdx` with your own introduction. Keep the file, because the landing page's *Start reading* button opens it.
3. Put your own terms in `content/glossary.json`, or [remove the glossary](/docs/glossary#remove-the-glossary).

Then add your notes to `content/docs/`. [Pages and sidebar](/docs/pages) explains how.

</Step>
<Step>

### Save it to GitHub

```bash
git init
git add .
git commit -m "My notes"
```

Then create an empty repository on GitHub and follow its instructions to push. Git keeps every change, and any computer gets the notes with `git pull`. The *Last updated* date of each page also comes from its latest commit, so a page you haven't committed shows no date.

Putting the site online is a separate step. See [Deployment](/docs/deployment).

</Step>
</Steps>

## Commands

Run these in your site's folder:

| Command | What it does |
| --- | --- |
| `npm run dev` | Starts the site at localhost:3000 while you write |
| `npm run build` | Builds the whole site as plain files in `out/` |
| `npm start` | Shows the built `out/` folder locally, exactly as it will be published |
| `npm run types:check` | Checks the code for mistakes (useful after an update) |

## What's in the site

Only the files that Next.js and Fumadocs need to exist in your app. Each one is a few lines that call the theme, so later versions reach your site through `npm update` (see [Updates and versions](/docs/updates)):

| File | What it does | Edit it? |
| --- | --- | --- |
| `site.config.ts` | Your site's name, links, colour and languages | **Yes** |
| `content/docs/` | Your notes, and `meta.json` files for the sidebar order. `index.mdx` is the first page; `example/` is the sample | **Yes** |
| `content/glossary.json` | Your glossary terms | **Yes** |
| `app/icon.svg` | The browser-tab icon | If you want your own |
| `app/layout.tsx` | Fonts, then `NotesRoot`: the accent, search and page transitions | No |
| `app/global.css` | Loads Tailwind CSS and the theme | No |
| `app/(home)/` | The landing page, built from your notes | No |
| `app/docs/` | The notes layout and each note's page | No |
| `app/api/search/` | The search index, built once and searched in the browser | No |
| `app/og/docs/` | Share images: the picture a link to a note gets in chat apps | No |
| `app/llms*/` | Plain-text copies of the notes for AI assistants, and *Copy Markdown* | No |
| `lib/source.ts` | Reads the notes from `content/docs/` | No |
| `next.config.mjs` | Static export settings, for hosting without a server | No |
| `postcss.config.mjs`, `tsconfig.json` | Tailwind CSS and TypeScript settings | No |

What search, share images and the plain-text copies do, and what each needs, is on [Built-in features](/docs/features).
