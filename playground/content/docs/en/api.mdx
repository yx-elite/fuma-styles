A site made with `npm create notestack` already imports everything it needs, so you only need this page to go further: your own landing page, several languages, or your own components.

The package has five import paths and a CSS file. Each name comes from one path only: `createNotesPage` is in `notestack/routes`, not in `notestack`. The *File* column names the file in a one-language site. On a site with `languages`, the pages and layouts move under `app/[lang]/` ([Languages](/docs/languages#update-the-layouts)). Your editor shows each prop and its type as you type.

## notestack

Layouts, the landing page, components and the site config.

```ts
import { NotesRoot, notesMetadata } from 'notestack';
import type { SiteConfig } from 'notestack';
```

| Export | What it does | File |
| --- | --- | --- |
| `defineSiteConfig(config)` | Checks your settings against `SiteConfig` and returns them unchanged. [Configuration](/docs/configuration) | `site.config.ts` |
| `NotesRoot` | The whole root layout: `<html>`, `<body>`, the accent, search and the page transitions. Props: `site`, `className` for the font variables, `language` on a site with `languages` | `app/layout.tsx` |
| `notesMetadata(site, language?)` | The root layout's metadata: *Page · Site* titles, the description, and `url` as the base for share images | `app/layout.tsx` |
| `NotesLayout` | The docs layout: header, sidebar with the banner and quick links, phone and tablet menus. Props: `site`, `tree` (`source.getPageTree()`) | `app/docs/layout.tsx` |
| `NotesHomeLayout` | The landing page's header. Props: `site`, `tree` | `app/(home)/layout.tsx` |
| `NotesHome` | The landing page, built from your notes and config. Props: `site`, `source`. [Landing page](/docs/landing-page) | `app/(home)/page.tsx` |
| `Callout` | A tinted box with an icon and a title. Notes use it without importing it; import it for your own pages. [Callouts](/docs/callouts) | Notes, your own pages |
| `Glossary` | The A to Z list of terms, with a filter box and a letter bar. Prop: `terms`. [Glossary](/docs/glossary) | `content/docs/glossary.mdx` |
| `siteFor(site, language)` | The config as one language sees it: that language's `translations` on top, and links that stay inside the language. [Your own landing page](/docs/landing-page#several-languages) | Files in `app/[lang]/` |
| `defaultLanguageOf(site)` | The site's default language: the first of `languages`, else `language`, else `en` | `app/(root)/layout.tsx` |
| `notesLanguages(site)` | Fumadocs' language settings for `loader()`. Nothing on a one-language site | `lib/source.ts` |
| `LanguageRedirect` | The page at `/` on a site with `languages`: sends readers to the language they read last, else their browser's. Prop: `site` | `app/(root)/page.tsx` |

Types, for your own code:

| Type | What it describes |
| --- | --- |
| `SiteConfig` | Every option in `site.config.ts` |
| `SiteTranslation` | The options one language can change, in `translations` |
| `StartSection` | The landing page's *Get started* section, in `start` |
| `NotesText` | Every phrase the theme shows, for `text` ([Built-in text](/docs/languages#built-in-text)) |
| `CalloutProps` | The props of `Callout` |
| `GlossaryTerm` | One entry of `content/glossary.json`: `term`, `definition`, and an optional `href` and `label` |

## notestack/routes

The docs page and the routes that serve search, share images and the copies for AI assistants. Server only: import it from files in `app/`. Each helper returns what its route file exports. Keep `export const revalidate = false;` (and `dynamicParams`, where the starter has it) written out in each file: Next.js reads those lines without running the code.

```ts title="app/api/search/route.ts"
import { searchRoute } from 'notestack/routes';
import { source } from '@/lib/source';

export const revalidate = false;
export const GET = searchRoute(source);
```

| Export | What it does | File |
| --- | --- | --- |
| `createNotesPage({ source, site, components?, repoDir? })` | The docs page. Returns `Page`, `generateMetadata` and `generateStaticParams`. `components` adds your own MDX components ([Your own components](/docs/advanced#your-own-components)); `repoDir` is the site's folder in a bigger repository ([Advanced](/docs/advanced#a-site-inside-a-bigger-repository)) | `app/docs/[[...slug]]/page.tsx` |
| `searchRoute(source)` | The search index, built once when the site builds and searched in the browser. [Search](/docs/features#search) | `app/api/search/route.ts` |
| `ogImageRoute({ source, site })` | A share image for every page. Returns `GET` and `generateStaticParams`. [Share images](/docs/features#share-images) | `app/og/docs/[...slug]/route.tsx` |
| `llmsTxtRoute(source)` | `/llms.txt`, a list of every page | `app/llms.txt/route.ts` |
| `llmsFullRoute(source)` | `/llms-full.txt`, every page in one file | `app/llms-full.txt/route.ts` |
| `llmsPageRoute(source)` | Each page as Markdown, for the *Copy Markdown* button. Returns `GET` and `generateStaticParams`. [Copies for AI assistants](/docs/features#copies-for-ai-assistants) | `app/llms.mdx/[...path]/route.ts` |

## notestack/mdx

```ts
import { getMDXComponents } from 'notestack/mdx';
```

| Export | What it does |
| --- | --- |
| `getMDXComponents(components?, { site })` | Every component a note can use, Fumadocs' and Notestack's, with yours on top. `createNotesPage` already calls it; you need it only to render MDX yourself |

## notestack/source

```ts title="lib/source.ts"
import { notesSourcePlugins } from 'notestack/source';
```

| Export | What it does | File |
| --- | --- | --- |
| `notesSourcePlugins` | Plugins for `loader()`: `icon:` in a page's frontmatter or a `meta.json` shows that [Lucide](https://lucide.dev/icons) icon in the sidebar. [Frontmatter](/docs/pages#frontmatter) | `lib/source.ts` |

## notestack/next

```js title="next.config.mjs"
import { createMDX } from 'fumadocs-mdx/next';
import { withNotestack } from 'notestack/next';

export default createMDX()(withNotestack());
```

| Export | What it does | File |
| --- | --- | --- |
| `withNotestack(config?)` | The settings a static site needs: `output: 'export'`, `trailingSlash` and unoptimised images. Your own Next.js options are kept; these three always win. [Next.js options](/docs/advanced#nextjs-options) | `next.config.mjs` |

This file runs in Node before Next.js starts, so it holds no React.

## notestack/theme.css

The whole design. Import it after Tailwind:

```css title="app/global.css"
@import 'tailwindcss';
@import 'notestack/theme.css';
```

The variables you can change, such as `--ns-accent` and `--ns-font-display`, are in [Theme](/docs/theme#css-variables).

## Anything else

Only the names on this page are public. The package has more inside, used by the layouts, and those can change in any version. If you need one of them, [open an issue](https://github.com/yx-elite/notestack/issues) and say what for.
