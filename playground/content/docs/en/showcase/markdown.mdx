## Typography

### Heading level 3

Listed in *On this page*, indented under its `##` heading.

#### Heading level 4

Not listed in *On this page*.

##### Heading level 5

Should still look like a heading, not like bold text.

###### Heading level 6

The smallest heading, close to body text in size.

### Paragraphs

A paragraph of normal length. Body text should be comfortable to read for a long time, with enough space between lines.

A long paragraph, to check how dense text reads. Caches keep a copy of data close to where it is used, so later reads are faster and cheaper. The trade-off is freshness: a cached copy can become stale when the original changes. Some systems expire entries after a fixed time, some remove them when the original changes, and some do both. The right choice depends on how often the data changes and how much harm an old value can do.

Short line.

### Emphasis

**Bold**, *italic*, ***bold italic***, ~~strikethrough~~ and <mark>highlighted text</mark>. Bold inside a sentence: the **origin** is where the original data lives.

### Inline code

Set `Cache-Control` to `max-age=3600`. Long inline code must wrap: `content/docs/networking/routing/static-and-dynamic-routes/index.mdx`. Inside bold and a link: **`TTL` means time to live**, and see [the `create` command](/docs/installation).

### Footnotes

Caches trade freshness for speed[^1]. DNS answers are cached at several levels[^dns].

[^1]: A stale entry is one whose original has changed since it was cached.

[^dns]: The browser, the operating system and the resolver can all hold a copy.

### Rich content in cells

| Setting | Example | Notes |
| --- | --- | --- |
| `Cache-Control` | `max-age=3600` | Seconds a copy stays fresh. See [Configuration](/docs/configuration). |
| `ETag` | `"33a64df5"` | A version tag. It **changes** when the content changes. |
| `Vary` | `Accept-Encoding` | Keeps a separate copy per value. ~~Rarely~~ often needed. |

### Wide table

On a phone, the table scrolls sideways, not the page.

| Protocol | Layer | Port | Transport | Encrypted | Typical use | Example | Notes |
| --- | --- | --- | --- | --- | --- | --- | --- |
| HTTP | Application | 80 | TCP | No | Web pages | `curl http://example.com` | Plain text on the wire |
| HTTPS | Application | 443 | TCP | Yes | Web pages | `curl https://example.com` | HTTP inside TLS |
| DNS | Application | 53 | UDP, or TCP for large answers | No | Name lookups | `dig example.com` | Answers are cached at several levels |

### Long text in cells

| Strategy | How it works | When to use it |
| --- | --- | --- |
| Cache-aside | The application checks the cache first. On a miss it reads the origin, then writes the result into the cache for next time. | Read-heavy data that can be a little stale, where only requested items should take up cache space. |
| Write-through | Every write goes to the cache and the origin together, so the cache is always current. | Data that is read soon after it is written and must not be stale. |
