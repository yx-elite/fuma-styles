## Term and meaning lists

The format used across the notes: a term in code, then what it means.

- `TTL`: how long a cached answer stays valid.
- `hit`: the answer was found in the cache.
- `miss`: the answer had to come from the origin.
- `eviction`: an entry was removed to make space.

The same with bold terms:

- **Write-through:** every write goes to the cache and the origin at once.
- **Write-back:** writes go to the cache first and reach the origin later.
- **Cache-aside:** the application reads the cache and fills it on a miss.

## Long items

- A long list item that wraps over several lines. It checks the indent of the second line: the wrapped text should line up with the first word, not with the bullet, so a long item still reads as one block.
- A list item with two paragraphs.

  The second paragraph belongs to the same item. It needs the same indent and a little space above it.

- A list item with a code block inside:

  ```bash
  dig +short example.com
  ```

## Exam scenarios

The pattern used at the end of each note:

- **Users worldwide, one Region, slow pages** → cache content at the edge, because it moves copies closer to users.
- **Data must survive a data centre failure** → spread across at least two zones, because one zone can fail on its own.
- **Old prices shown after an update** → shorten the TTL or clear the cache on change, because the cached copy is stale.
